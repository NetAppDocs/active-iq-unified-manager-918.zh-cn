= 了解 Active IQ Unified Manager 集群中的仲裁和 epsilon
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
Quorum 和 epsilon 是衡量集群健康和功能的重要指标，它们共同表明集群如何解决潜在的通信和连接挑战。

_仲裁_ 是集群完全正常运行的前提条件。当集群处于仲裁状态时，大多数节点处于正常运行状态，并且能够相互通信。当仲裁丢失时，集群将失去执行正常集群操作的能力。在任意给定时刻，只有一组节点能够拥有仲裁，因为所有节点共同共享单一的数据视图。因此，如果允许两个无法相互通信的节点以不同的方式修改数据，则将无法再将数据协调为单一的数据视图。

集群中的每个节点都参与一个投票协议，该协议会选举一个节点作为主节点；其余每个节点均为辅助节点。主节点负责在整个集群中同步信息。形成法定人数后，将通过持续投票来维持。如果主节点离线且集群仍处于法定人数状态，则由保持在线的节点选举出新的主节点。

由于具有偶数个节点的集群中可能存在并列，因此一个节点具有称为 epsilon 的额外分数投票权。如果一个大型集群中两个相等部分之间的连接发生故障，而所有节点运行状况均正常，则具有 epsilon 的那组节点将保持仲裁关系。例如，下图显示了一个四节点集群，其中两个节点发生故障。但是，由于其中一个幸存的节点具有 epsilon，因此即使没有大多数运行状况良好的节点，集群仍将保持仲裁状态。

image::../media/epsilon_preserving_quorum.gif[本图四周的文字提供了相关说明。]

创建集群时，Epsilon 将自动分配给第一个节点。如果持有 epsilon 的节点变得不健康、接管其高可用性配对节点或被其高可用性配对节点接管，则 epsilon 将自动重新分配给不同 HA 对中的健康节点。

使节点离线会影响集群保持仲裁状态的能力。因此，如果您尝试执行会导致集群脱离仲裁，或者使其距离丢失仲裁仅差一次中断的操作， ONTAP 将发出警告消息。您可以在高级权限级别使用 cluster quorum-service options modify 命令来禁用仲裁警告消息。

一般来说，假设集群节点之间具有可靠的连接，较大的集群比较小的集群更稳定。与两个节点的集群相比，在 24 个节点的集群中更容易维持一半节点加 epsilon 的简单多数法定人数要求。

双节点集群在维护仲裁方面存在一些独特的挑战。双节点集群使用集群 HA，其中两个节点均不具有 epsilon；相反，系统会持续轮询这两个节点，以确保如果一个节点发生故障，另一个节点对数据拥有完全读写访问权限，并可访问逻辑接口和管理功能。
