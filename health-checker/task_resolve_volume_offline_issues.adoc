= 解决 Active IQ Unified Manager 中的卷脱机问题
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
此工作流程提供了如何评估和解决 Unified Manager 可能在事件管理清单页面中显示的卷脱机事件的示例。在此场景中，您是使用 Unified Manager 对一个或多个卷脱机事件进行故障排除的管理员。

.开始之前
您必须具有操作员、应用程序管理员或存储管理员角色。

卷可能因以下几个原因被报告为离线：

* SVM 管理员已故意使卷脱机。
* 卷的托管集群节点已关闭，并且到其 HA 对伙伴的存储故障转移也已失败。
* 卷的托管存储虚拟机（SVM）已停止，因为托管该 SVM 的根卷的节点已停机。
* 由于两个 RAID 磁盘同时出现故障，此卷的托管聚合已关闭。


您可以使用事件管理清单页面以及群集/运行状况、存储虚拟机/运行状况和卷/运行状况详细信息页面来确认或消除其中一种或多种可能性。

.步骤
. 在左侧导航窗格中，单击*事件管理*。
. 在*事件管理*清单页面中，选择*活动可用性事件*。
. 单击为“Volume Offline”事件显示的超文本链接。
+
此时将显示可用性意外事件的“事件详细信息”页面。

. 在该页面上，查看备注，以确定是否有迹象表明 SVM 管理员已将相关卷脱机。
. 在*事件*详细信息页面上，您可以查看以下一个或多个任务的信息：
+
** 查看“原因”字段中显示的信息，以获得可能的诊断指导。
+
在此示例中，“原因”字段中的信息仅通知您此卷已脱机。

** 检查 Notes and Updates（注释和更新）区域，查看是否有任何迹象表明 SVM 管理员故意使相关卷脱机。
** 单击事件源（在本例中为离线报告的卷）以获取有关该卷的详细信息。
** 将此事件分配给管理员。
** 请确认该事件，或在适当情况下将其标记为已解决。
