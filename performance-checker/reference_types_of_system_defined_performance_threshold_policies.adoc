= 了解 Active IQ Unified Manager 中系统定义的性能阈值策略
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
Unified Manager 提供一些标准阈值策略，可监控集群性能并自动生成事件。默认情况下，这些策略处于启用状态，当超出受监控的性能阈值时，它们会生成警告或信息事件。

[NOTE]
====
Cloud Volumes ONTAP、ONTAP Edge 或 ONTAP Select 系统上未启用系统定义的性能阈值策略。

====
如果从任何系统定义的性能阈值策略接收到不必要的事件，则可以从“事件设置”页面禁用单个策略的事件。



[[cluster-threshold-policies]]
== 集群阈值策略

默认情况下，系统定义的集群性能阈值策略分配给由 Unified Manager 监控的每个集群：

* *集群负载不平衡*
+
识别一个节点在比集群中的其他节点高得多的负载下运行的情况，从而可能影响工作负载延迟。

+
它通过比较集群中所有节点的性能容量使用值来实现此目的，以查看是否有任何节点超过 30% 阈值的时间超过 24 小时。这是一个警告事件。

* *集群容量不平衡*
+
标识一个聚合的使用容量远高于集群中其他聚合的情况，因此可能会影响操作所需的空间。

+
它通过比较集群中所有聚合的已用容量值来实现此目的，以查看任何聚合之间是否存在 70% 的差异。这是一个警告事件。





[[node-threshold-policies]]
== 节点阈值策略

默认情况下，系统定义的节点性能阈值策略会分配给由 Unified Manager 监控的集群中的每个节点：

* *已违反已用性能容量阈值*
+
识别单个节点运行超出其运行效率界限的情况，从而可能影响工作负载延迟。

+
它通过查找使用超过 100% 的性能容量且持续超过 12 小时的节点来实现此目的。这是一个警告事件。

* *节点 HA 对已过度利用*
+
确定 HA 对中的节点运行效率高于 HA 对运行效率范围的情况。

+
它通过查看 HA 对中两个节点的性能容量使用值来实现此目的。如果两个节点使用的总性能容量超过 200% 且持续 12 小时以上，则控制器故障转移将影响工作负载延迟。这是一个信息事件。

* *节点磁盘碎片*
+
识别聚合中的一个或多个磁盘碎片化，减慢关键系统服务并可能影响节点上工作负载延迟的情况。

+
它通过查看节点上所有聚合的某些读取和写入操作比率来实现。在 SyncMirror 重新同步期间或在磁盘清理操作期间发现错误时，也可能会触发此策略。这是一个警告事件。

+
[NOTE]
====
"\`节点磁盘碎片\`" 策略分析仅限 HDD 的聚合；不分析 Flash Pool、SSD 和 FabricPool 聚合。

====




[[aggregate-threshold-policies]]
== 聚合阈值策略

系统定义的聚合性能阈值策略默认分配给由 Unified Manager 监控的集群中的每个聚合：

* *聚合磁盘使用过度*
+
识别聚合运行超出其运行效率限制的情况，从而可能影响工作负载延迟。它通过查找聚合中的磁盘利用率超过 95% 且持续时间超过 30 分钟的聚合来识别这些情况。然后，此多条件策略将执行以下分析以帮助确定问题的原因：

+
** 聚合中的磁盘当前是否正在进行后台维护活动？
+
磁盘可能正在进行的一些后台维护活动包括磁盘重建、磁盘清理、SyncMirror 重新同步和重新计算奇偶校验。

** 磁盘架光纤通道互连中是否存在通信瓶颈？
** 聚合中的可用空间是否太少？仅当三个从属策略中的一个（或多个）也被视为违规时，才会为此策略发出警告事件。如果只有聚合中的磁盘利用率超过 95%，则不会触发性能事件。




[NOTE]
====
“`聚合磁盘过度使用`”策略分析仅 HDD 聚合和 Flash Pool（混合）聚合；不分析 SSD 和 FabricPool 聚合。

====


[[workload-latency-threshold-policies]]
== 工作负载延迟阈值策略

系统定义的工作负载延迟阈值策略将分配给具有已配置性能服务级别策略的任何工作负载，该策略具有定义的 "`expected latency`" 值：

* *已违反性能服务级别定义的工作负载卷/LUN 延迟阈值*
+
标识已超出“`预期延迟`”限制且影响工作负载性能的卷（文件共享）和 LUN。这是一个警告事件。

+
它通过查找在过去一小时内有 30% 的时间超过预期延迟值的工作负载来实现此目的。





[[qos-threshold-policies]]
== QoS 阈值策略

系统定义的 QoS 性能阈值策略将分配给配置了 ONTAP QoS 最大吞吐量策略（IOPS、IOPS/TB 或 MB/s）的任何工作负载。当工作负载吞吐量值比配置的 QoS 值低 15% 时，Unified Manager 会触发事件：

* *QoS 最大 IOPS 或 MB/s 阈值*
+
标识已超出其 QoS 最大 IOPS 或 MB/s 吞吐量限制并影响工作负载延迟的卷和 LUN。这是一个警告事件。

+
将单个工作负载分配给策略组时，它通过查找在前一小时的每个收集期间超过分配的 QoS 策略组中定义的最大吞吐量阈值的工作负载来实现此目的。

+
当多个工作负载共享单个 QoS 策略时，它通过将该策略中所有工作负载的 IOPS 或 MB/s 相加，并将该总数与阈值进行比较来实现这一点。

* *QoS 峰值 IOPS/TB 或带有块大小阈值的 IOPS/TB*
+
标识已超过其自适应 QoS 峰值 IOPS/TB 吞吐量限制（或带块大小限制的 IOPS/TB），且正在影响工作负载延迟的卷。这是一个警告事件。

+
为此，它根据每个卷的大小将自适应 QoS 策略中定义的峰值 IOPS/TB 阈值转换为 QoS 最大 IOPS 值，然后查找在前一小时的每个性能收集期间超过 QoS 最大 IOPS 的卷。

+
[NOTE]
====
仅当集群安装了 ONTAP 9.3 及更高版本软件时，此策略才应用于卷。

====
+
当自适应 QoS 策略中定义了"`block size`"元素时，系统会根据每个卷的大小将阈值转换为 QoS 最大 MB/s 值。然后，系统会查找在前一小时内每个性能收集周期中超过 QoS 最大 MB/s 的卷。

+
[NOTE]
====
仅当集群安装了 ONTAP 9.5 及更高版本软件时，此策略才应用于卷。

====
