= 了解 Active IQ Unified Manager 如何计算预期性能范围
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
延迟预测是对特定时间内预期上限和下限性能值的预测。对于工作负载延迟，上限值构成性能阈值。当实际值超过性能阈值时，Unified Manager 会触发动态性能事件。

例如，在上午 9:00 至下午 5:00 的正常工作时间内，大多数员工可能会在上午 9:00 至上午 10:30 之间查看电子邮件。对电子邮件服务器的需求增加意味着在此期间后端存储的工作负载活动增加。员工可能会注意到电子邮件客户端的响应时间很慢。

在中午 12:00 至下午 1:00 之间的午餐时间以及下午 5:00 之后的工作日结束时，大多数员工可能会离开电脑。对电子邮件服务器的需求通常会下降，同时也会降低对后端存储的需求。或者，可能会有计划内的工作负载操作，例如存储备份或病毒扫描，这些操作在下午 5:00 之后开始，并增加后端存储上的活动。

在几天内，工作负载活动的增加和减少决定了活动的预期范围（延迟预测），以及工作负载的上限和下限。当对象的实际工作负载活动在上限或下限之外，并且在一段时间内保持在边界之外时，这可能表明对象被过度使用或未充分使用。



[[how-the-latency-forecast-is-formed]]
== 延迟预测是如何形成的

Unified Manager 必须收集至少 3 天的工作负载活动，然后才能开始分析，并且才能在 GUI 中显示 I/O 响应时间的延迟预测。最低要求的数据收集不考虑工作负载活动发生的所有更改。在收集前 3 天的活动后，Unified Manager 会在每 24 小时的凌晨 12:00 调整延迟预测，以反映工作负载活动的变化，并建立更准确的动态性能阈值。

[NOTE]
====
夏令时 （DST） 会更改系统时间，从而改变受监控工作负载的性能统计信息的延迟预测。Unified Manager 会立即开始更正延迟预测，此过程大约需要 15 天才能完成。在此期间，您可以继续使用 Unified Manager，但由于 Unified Manager 使用延迟预测来检测动态事件，某些事件可能不准确。在时间更改之前检测到的事件不受影响。
