= 响应 Active IQ Unified Manager 中的节点资源过度利用事件
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
当单个节点运行超出其运行效率的界限，从而可能影响工作负载延迟时，Unified Manager 会生成节点资源过度使用的警告事件。这些系统定义的事件提供了在许多工作负载受到延迟影响之前纠正潜在性能问题的机会。

.开始之前
* 您必须具有操作员、应用程序管理员或存储管理员角色。
* 必须有新的或过时的性能事件。


Unified Manager 通过查找使用超过 100% 性能容量超过 30 分钟的节点，为节点资源过度使用策略违规生成警告事件。

您可以使用 System Manager 或 ONTAP 命令来更正此类型的性能问题，包括以下任务：

* 创建 QoS 策略并将其应用于任何过度使用系统资源的卷或 LUN
* 降低已应用工作负载的策略组的 QoS 最大吞吐量限制
* 将工作负载移动到其他聚合或节点
* 通过向节点添加磁盘或升级为 CPU 更快且 RAM 更大的节点来提高容量


.步骤
. 显示*事件详细信息*页面以查看有关该事件的信息。
. 查看*描述*，其中描述了导致此事件的阈值违规行为。
+
例如，消息 "`Perf.simplicity-02 上的 Capacity Used 值为 139%，已触发 WARNING 事件以确定 Data Processing 单元中的潜在性能问题。`" 表示节点 simplicity-02 上的性能容量被过度使用并影响节点性能。

. 在*系统诊断*部分下，查看三个图表：一个用于节点上使用的性能容量，一个用于顶级工作负载使用的平均存储 IOPS，一个用于顶级工作负载上的延迟。以这种方式排列时，您可以查看哪些工作负载是节点上延迟的原因。
+
您可以通过将光标移到 IOPS 图表上来查看哪些工作负载应用了 QoS 策略，哪些未应用 QoS 策略。

. 在*建议操作*部分下，查看建议并确定应执行哪些操作以避免工作负载的延迟增加。
+
如果需要，请单击 *帮助* 按钮以查看有关您可以执行的建议操作的更多详细信息，以尝试解决性能事件。
