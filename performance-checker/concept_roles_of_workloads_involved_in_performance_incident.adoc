= 在 Active IQ Unified Manager 中识别性能事件中的工作负载角色
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
Unified Manager 使用角色来识别工作负载在性能事件中的参与度。角色包括受害者、欺凌者和鲨鱼。用户定义的工作负载可能同时是受害者、欺凌者和鲨鱼。

|===
| 角色 | 问题描述 


 a| 
受影响
 a| 
由于过度使用集群组件的其他工作负载（称为恶霸）而导致性能下降的用户定义工作负载。仅将用户定义的工作负载标识为受害者。Unified Manager 根据延迟的偏差来识别受害者工作负载，其中事件期间的实际延迟比其延迟预测（预期范围）大大增加。



 a| 
抢占资源
 a| 
用户定义或系统定义的工作负载，其过度使用集群组件导致其他工作负载（称为受害者）的性能降低。Unified Manager 根据集群组件的使用偏差来识别欺凌工作负载，其中在事件期间的实际使用量比其预期的使用范围大大增加。



 a| 
强占资源的工作负载
 a| 
与事件中涉及的所有工作负载相比，集群组件的使用率最高的用户定义工作负载。Unified Manager 根据事件期间集群组件的使用情况来识别 shark 工作负载。

|===
集群上的工作负载可以共享许多集群组件，例如用于网络和数据处理的聚合和 CPU。当工作负载（如卷）增加其对集群组件的使用，以至于组件无法有效地满足工作负载需求时，该组件就处于争用状态。过度使用集群组件的工作负载是欺凌者。共享这些组件且其性能受到欺凌者影响的其他工作负载是受害者。来自系统定义工作负载（例如重复数据删除或 Snapshot 副本）的活动也可能升级为 "`bullying`"。

当 Unified Manager 检测到事件时，它会识别所涉及的所有工作负载和集群组件，包括导致事件的恶霸工作负载、发生争用的集群组件以及由于恶霸工作负载的活动增加而导致性能下降的受害者工作负载。

[NOTE]
====
如果 Unified Manager 无法识别恶霸工作负载，它只会对受害者工作负载和所涉及的集群组件发出警报。

====
Unified Manager 可以识别作为欺凌工作负载受害者的工作负载，并确定这些相同的工作负载何时成为欺凌工作负载。工作负载可能会欺凌自身。例如，受策略组限制所限制的高性能工作负载会导致策略组中的所有工作负载（包括其自身）受到限制。在持续发生的性能事件中，作为欺凌者或受害者的工作负载可能会更改其角色，或者不再是该事件的参与者。
