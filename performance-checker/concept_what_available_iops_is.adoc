= 了解 Active IQ Unified Manager 中的可用 IOPS
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
可用 IOPS 计数器标识可在资源达到其限制之前添加到节点或聚合中的剩余 IOPS 数量。

节点可提供的总 IOPS 取决于节点的物理特性，例如 CPU 数量、CPU 速度和 RAM 容量。聚合可提供的总 IOPS 基于磁盘的物理属性，例如 SATA、SAS 或 SSD 磁盘。

聚合中所有卷的总 IOPS 可能与聚合的总 IOPS 不匹配。以下知识库文章对此进行了讨论：KB link:https://kb.netapp.com/Advice_and_Troubleshooting/Data_Infrastructure_Management/Active_IQ_Unified_Manager/Why_does_the_sum_of_all_volume_IOPs_in_an_aggregate_not_match_the_aggregate_IOPs%3F["为什么聚合中所有卷 IOPs 的总和与聚合 IOPs 不匹配？"]

虽然性能空闲容量计数器提供仍然可用的资源的百分比，但可用的 IOPS 计数器会告诉您在达到最大性能容量之前可以添加到资源中的 IOPS（工作负载）的确切数量。

例如，如果您使用的是一对 FAS2520 和 FAS8060 存储系统，则性能容量空闲值为 30% 意味着您有一些空闲性能容量。但是，该值并不能让您了解还可以向这些节点部署多少个工作负载。可用 IOPS 计数器可能显示 FAS8060 上有 500 个可用 IOPS，但 FAS2520 上只有 100 个可用 IOPS。

下图显示了节点的示例延迟与 IOPS 曲线。

image::../media/available_iops.gif[显示节点的示例延迟与 IOPS 曲线的 UI 屏幕截图。]

资源可以提供的最大 IOPS 数是性能容量使用计数器为 100%（最佳点）时的 IOPS 数。操作点标识节点当前以 100K IOPS 运行，延迟为 1.0 ms/op。根据从节点捕获的统计数据，Unified Manager 确定节点的最大 IOPS 为 160K，这意味着有 60K 空闲或可用 IOPS。因此，您可以向此节点添加更多工作负载，以便更有效地使用您的系统。

[NOTE]
====
当资源中的用户活动极少时，可用 IOPS 值是假设基于每个 CPU 核心约 4,500 IOPS 的通用工作负载来计算的。这是因为 Unified Manager 缺乏准确估计所服务工作负载特征的数据。
