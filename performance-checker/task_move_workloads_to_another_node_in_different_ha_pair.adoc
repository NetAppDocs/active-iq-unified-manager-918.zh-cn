= 将工作负载移动到 Active IQ Unified Manager 中不同 HA 对中的另一个节点
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
您可以使用 Unified Manager 帮助识别不同 HA 对中节点上的聚合，该节点的繁忙程度低于当前运行工作负载所在的 HA 对。然后，您可以将所选卷移动到新 HA 对上的聚合。将高性能工作负载移动到不太繁忙的节点上的聚合中，可以使两个节点上的工作负载更高效地运行。

.开始之前
* 您必须具有操作员、应用程序管理员或存储管理员角色。
* 您的集群必须至少由两个 HA 对组成；如果集群中只有一个 HA 对，则不能使用此补救过程。
* 您必须已记录 HA 对中当前存在性能问题的两个节点的名称。
* 您必须已记录节点接收性能事件的日期和时间。
* Unified Manager 必须已收集并分析了一个月或更长时间的性能数据。


这些步骤可帮助您识别以下资源，以便将高性能工作负载移动到其他 HA 对上利用率较低的节点：

* 同一集群中不同 HA 对中利用率较低的节点
* 利用率最低的新节点上的聚合
* 当前节点上性能最高的卷


.步骤
. 识别属于同一集群上不同 HA 对的节点：
+
.. 在左侧导航窗格中，单击*存储* > *集群*，然后从视图菜单中选择*性能* > *所有集群*。
+
此时将显示“性能：所有群集”视图。

.. 单击当前集群的*节点数量*字段中的数字。
+
此时将显示“性能：所有节点”视图。

.. 记录下与当前存在性能问题的 HA 对不同的其他 HA 对中的节点名称。


. 确定新 HA 对中利用率最低的节点：
+
.. 单击*利用率*列，按利用率最低对节点进行排序。
+
您还可以识别具有最大*可用容量*的节点。这提供了一个潜在节点列表，您可能希望将工作负载移动到这些节点。

.. 写下要将工作负载移动到的节点的名称。


. 识别新节点上利用率最低的聚合：
+
.. 在左侧导航窗格中，单击*存储* > *聚合*，然后从视图菜单中选择*性能* > *所有聚合*。
+
此时将显示“性能：所有聚合”视图。

.. 单击*过滤*，从左侧下拉菜单中选择*节点*，在文本字段中键入节点的名称，然后单击*应用过滤器*。
+
“性能：所有聚合”视图将与此节点上可用的聚合列表一起重新显示。

.. 单击*利用率*列，按利用率最低对聚合进行排序。
+
您还可以识别具有最大*空闲容量*的聚合。这将提供一个潜在聚合列表，您可能希望将工作负载移动到这些聚合上。

.. 写下要将工作负载移动到的聚合的名称。


. 从接收事件的节点中识别高性能工作负载：
+
.. 返回此事件的*事件*详细信息页面。
.. 在*受影响的卷*字段中，单击第一个节点的卷数量的链接。
+
此时将显示"Performance: All Volumes （性能：所有卷）"视图，其中包含该节点上卷的筛选列表。

.. 单击*总容量*列，按分配的最大空间对卷进行排序。
+
这提供了可能需要移动的潜在卷的列表。

.. 记下要移动的卷的名称，以及它们所在的当前聚合的名称。
.. 对属于此事件的第二个节点执行步骤 4c 和 4d，以确定可能也要从该节点移动的卷。


. 将卷移动到您确定在新节点上利用率较低的聚合。
+
您可以使用 ONTAP System Manager、OnCommand Workflow Automation、ONTAP 命令或这些工具的组合来执行移动操作。



几天后，请检查您是否从此节点或聚合接收到相同类型的事件。
