= 分析 Active IQ Unified Manager 中的性能事件和通知
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
性能事件会通知您由集群组件上的争用引起的工作负载上的 I/O 性能问题。Unified Manager 将分析事件，以确定所涉及的所有工作负载、发生争用的组件以及事件是否仍然是您可能需要解决的问题。

Unified Manager 监控集群上卷的 I/O 延迟（响应时间）和 IOPS（操作）。例如，当其他工作负载过度使用集群组件时，该组件会处于争用状态，无法以最佳水平运行来满足工作负载需求。使用相同组件的其他工作负载的性能可能会受到影响，从而导致其延迟增加。如果延迟超过动态性能阈值，Unified Manager 将触发性能事件以通知您。



[[event-analysis]]
== 事件分析

Unified Manager 使用过去 15 天的性能统计信息执行以下分析，以确定事件中涉及的受害工作负载、恶霸工作负载和集群组件：

* 识别延迟超过动态性能阈值的受害者工作负载，动态性能阈值是延迟预测的上限：
+
** 对于 HDD 或 Flash Pool 混合聚合（本地层）上的卷，仅当延迟大于 5 毫秒（ms）且 IOPS 大于每秒 10 次操作（ops/sec）时才会触发事件。
** 对于全 SSD 聚合或 FabricPool 聚合（云层）上的卷，仅当延迟大于 1 ms 且 IOPS 大于 100 ops/sec 时才会触发事件。


* 标识争用中的集群组件。
+
[NOTE]
====
如果集群互连处的受害工作负载延迟大于 1 毫秒，Unified Manager 会将其视为重大问题，并触发集群互连事件。

====
* 标识过度使用集群组件并导致其处于争用状态的欺凌工作负载。
* 根据集群组件利用率或活动的偏差对所涉及的工作负载进行排名，以确定哪些欺凌者对集群组件的使用率变化最大，哪些受害者受到的影响最大。


事件可能仅发生短暂的时间，并在其使用的组件不再发生争用后自行恢复。连续事件是指在五分钟间隔内对同一集群组件重复发生并保持活动状态的事件。对于连续事件，Unified Manager 在连续两个分析间隔期间检测到同一事件后会触发警报。

当事件解决后，它在 Unified Manager 中仍然可用，作为卷过去性能问题记录的一部分。每个事件都有一个唯一的 ID，用于标识事件类型以及所涉及的卷、集群和集群组件。

[NOTE]
====
单个卷可以同时涉及多个事件。

====


[[event-state]]
== 事件状态

事件可能处于以下状态之一：

* *活动*
+
指示性能事件当前处于活动状态（新建或已确认）。导致事件的问题尚未自行更正或尚未解决。存储对象的性能计数器仍高于性能阈值。

* *已废弃*
+
指示该事件不再处于活动状态。导致该事件的问题已自行更正或已解决。存储对象的性能计数器不再高于性能阈值。





[[event-notification]]
== 事件通知

事件显示在“仪表板”页面和用户界面的许多其他页面上，这些事件的警报将发送到指定的电子邮件地址。您可以在“事件详细信息”页面和“工作负载分析”页面上查看有关事件的详细分析信息并获取解决该事件的建议。



[[event-interaction]]
== 事件交互

在“事件详细信息”页面和“工作负载分析”页面上，您可以通过以下方式与事件进行交互：

* 将鼠标移到事件上会显示一条消息，显示检测到事件的日期和时间。
+
如果同一时间段存在多个事件，消息将显示事件数量。

* 单击单个事件将显示一个对话框，其中显示有关该事件的更详细信息，包括所涉及的集群组件。
+
竞争中的组件以红色圆圈突出显示。您可以单击 *View full analysis* 以在 Event details 页面上查看完整分析。如果同一时间段内存在多个事件，该对话框将显示最近三个事件的详细信息。您可以单击某个事件，以在 Event details 页面上查看事件分析。
