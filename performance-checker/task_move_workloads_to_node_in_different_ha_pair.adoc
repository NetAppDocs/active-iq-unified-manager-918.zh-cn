= 将工作负载移动到 Active IQ Unified Manager 中不同 HA 对的节点
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
您可以使用 Unified Manager 帮助识别不同高可用性（HA）对中的节点上的聚合，该节点具有比当前运行工作负载的 HA 对更多的可用性能容量。然后，您可以将所选卷移动到新 HA 对上的聚合。

.开始之前
* 您必须具有操作员、应用程序管理员或存储管理员角色。
* 您的集群必须至少由两个 HA 对组成
+
如果集群中只有一个 HA 对，则无法使用此修正过程。

* 您必须已记录 HA 对中当前存在性能问题的两个节点的名称。
* 您必须已记录节点接收性能事件的日期和时间。
* Unified Manager 必须已收集并分析性能数据一个月或更长时间。


将高性能工作负载移动到具有更高空闲性能容量的节点上的聚合，可以使两个节点上的工作负载都能更高效地执行。此过程可帮助您识别以下资源，以便您可以将高性能工作负载移动到在其他 HA 对上具有更多空闲性能容量的节点：

* 同一集群上具有最大空闲性能容量的不同 HA 对中的节点
* 具有最大空闲性能容量的新节点上的聚合
* 当前节点上性能最高的卷


.步骤
. 识别属于同一集群上不同 HA 对的节点：
+
.. 在*事件详细信息*页面上，单击节点所在的集群的名称。
+
集群详细信息显示在性能/集群登录页面中。

.. 在*摘要*页面上，单击*托管对象*窗格中的*节点*。
+
此集群上的节点列表显示在性能：所有节点视图中。

.. 记下不属于当前存在性能问题的 HA 对的其他 HA 对中的节点名称。


. 确定新 HA 对中具有最大可用性能容量的节点：
+
.. 在*性能：所有节点*视图上，单击*已用性能容量*列，按已用最少百分比对节点进行排序。
+
这提供了可能需要将工作负载移动到的潜在节点的列表。

.. 写下要将工作负载移动到的不同 HA 对上的节点的名称。


. 确定具有最大空闲性能容量的新节点上的聚合：
+
.. 在*性能：所有节点*视图上，单击该节点。
+
该节点的详细信息显示在性能/节点资源管理器页面中。

.. 在*查看和比较*菜单中，选择*此节点上的聚合*。
+
此节点上的聚合显示在网格中。

.. 单击*已用性能容量*列，按最少使用对聚合进行排序。
+
这提供了可能要将工作负载移动到的潜在聚合的列表。

.. 写下要将工作负载移动到的聚合的名称。


. 从接收事件的节点中识别高性能工作负载：
+
.. 返回此事件的*事件*详细信息页面。
.. 在*受影响的卷*字段中，单击第一个节点的卷数量的链接。
+
此时将显示"Performance: All Volumes （性能：所有卷）"视图，其中包含该节点上卷的筛选列表。

.. 单击*总容量*列，按分配的最大空间对卷进行排序。
+
这提供了可能需要移动的潜在卷的列表。

.. 记下要移动的卷的名称，以及它们所在的当前聚合的名称。
.. 对属于此事件的第二个节点执行步骤 4c 和 4d，以确定可能也要从该节点移动的卷。


. 将卷移动到您确定在新节点上具有最大可用性能容量的聚合。
+
您可以使用 ONTAP System Manager、OnCommand Workflow Automation、ONTAP 命令或这些工具的组合来执行移动操作。



几天后，您可以检查是否从此节点或聚合接收到相同类型的事件。
