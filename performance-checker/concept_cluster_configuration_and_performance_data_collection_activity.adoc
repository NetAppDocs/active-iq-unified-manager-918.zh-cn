= 在 Active IQ Unified Manager 中查看集群配置和性能数据
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
_集群配置数据_的收集间隔为 15 分钟。例如，添加集群后，需要 15 分钟才能在 Unified Manager UI 中显示集群详细信息。对集群进行更改时，此间隔也适用。

例如，如果将两个新卷添加到集群中的 SVM，则在下一个轮询间隔（可能长达 15 分钟）之后，UI 中会看到这些新对象。

Unified Manager 每五分钟从所有受监控的集群中收集当前的 _性能统计信息_。它分析这些数据以识别性能事件和潜在问题。它保留 30 天的五分钟历史性能数据和 180 天的一小时历史性能数据。这使您能够查看当月非常精细的性能详细信息，以及长达一年的一般性能趋势。

收集轮询偏移了几分钟，因此不会同时发送来自每个集群的数据，这可能会影响性能。

下表介绍了 Unified Manager 执行的收集活动：

|===
| 活动 | 时间间隔 | 问题描述 


 a| 
性能统计轮询
 a| 
每 5 分钟
 a| 
从每个集群收集实时性能数据。



 a| 
统计分析
 a| 
每 5 分钟
 a| 
每次统计轮询后，Unified Manager 都会将收集的数据与用户定义、系统定义和动态阈值进行比较。

如果已违反任何性能阈值，Unified Manager 将生成事件并向指定用户发送电子邮件（如果已配置）。



 a| 
配置轮询
 a| 
每 15 分钟
 a| 
从每个集群收集详细的清单信息，以识别所有存储对象（节点、SVM、卷等）。



 a| 
总结
 a| 
每小时
 a| 
将最新的 12 个五分钟性能数据收集汇总为每小时平均值。

每小时平均值用于一些 UI 页面，并保留 180 天。



 a| 
预测分析和数据修剪
 a| 
每天午夜后
 a| 
分析集群数据，为未来 24 小时的卷延迟和 IOPS 建立动态阈值。

从数据库中删除任何超过 30 天的五分钟性能数据。



 a| 
数据修剪
 a| 
每天凌晨 2 点后
 a| 
从数据库中删除任何超过 180 天的事件和超过 180 天的动态阈值。



 a| 
数据修剪
 a| 
每天凌晨 3:30 后
 a| 
从数据库中删除任何超过 180 天的一小时性能数据。

|===
